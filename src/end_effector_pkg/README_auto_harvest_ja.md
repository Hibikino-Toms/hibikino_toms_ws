# 自動収穫EE

`auto_harvest` ノードがEE用Picoシリアルを単独で所有し、センサー値を読みながら収穫工程を進めます。手動操作ノードはこのlaunchに含めません。実機では自動ノードと `pull_module_teleop` を同時に起動しないでください。

## 起動

模擬アーム・模擬EE・合成カメラで動作を確認します。

```bash
cd ~/hibikino_toms_ws
source /opt/ros/humble/setup.bash
colcon build --packages-select arm_controller_pkg end_effector_pkg vision_pkg
source install/setup.bash
ros2 launch vision_pkg vision_auto_harvest.launch.py
```

実機では、Picoへ自動収穫用ファームウェアを書き込んだ後に、D405・アーム・EEを確認して起動します。

```bash
ros2 launch vision_pkg vision_auto_harvest.launch.py backend:=dynamixel synthetic_camera:=false
```

初期化中はD405認識画面が起動していても、EE初期姿勢・原点の確認が終わるまでアームトラッカーはモーター通信・移動を開始しません。

## Picoスケッチ

既存の `module/pico_programs/pull_ee_teleop.ino` は変更せず、別スケッチ `module/pico_programs/pull_ee_auto_harvest/pull_ee_auto_harvest.ino` を追加しました。PlatformIOプロジェクトは `module/pico_programs/pull_ee_auto_harvest_pio` です。既存の `M<n>,PWM` と `STOP` に加えて、複数軸の同時駆動 `DRIVE p1,p2,p3,p4`、`KEEPALIVE`、停止中だけ実行する `ZERO_ENC4` を認識します。600msコマンド監視があり、動作中にPCまたはROS側が停止するとPicoがPWMを止めます。

VS CodeのPlatformIO IDEからは、このフォルダーを開いて `pull_ee_auto_harvest` 環境をビルドできます。シリアル番号を照合して書き込むスクリプトもあります。

```bash
cd ~/hibikino_toms_ws/module/pico_programs/pull_ee_auto_harvest_pio
./upload_auto_harvest.sh
```

スクリプトは `module/set_params.yaml` の `EE_PICO_SERIAL_NUMBER` と同じ `A437E4B324D4447A` を検出し、該当ポートをPlatformIOへ渡します。今回の書き込みでは `/dev/ttyACM2` のPico 2 Wを対象にし、PlatformIOのフラッシュ照合は100% `OK` でした。既存の手動用スケッチへ戻す場合は、元のスケッチを再書き込みします。

## 原点と初期化

ENC4は増分カウントで、Picoの再起動時にカウントが0になります。リミットスイッチがないため、0だけではレールの物理的な収納を確認できません。実機では、EEモーターが停止していることとレールが収納端にあることを目視で確認して、EE端末で `c` を押します。Picoは現在位置のカウントを0に登録し、pot1=1800、pot2=3930、pot3=1500、ENC4=0へセンサー帰還で初期化します。センサー値と原点確認が揃うまでアームは起動しません。

`c` の前提となるセンサー安定確認は、最新4サンプル（Picoは約5Hz）の最大値と最小値の幅で判定します。設定幅はPOT1=35、POT2=50、POT3=30、ENC4=1カウントです。2026-10-14のログに記録された停止中の変動幅（POT1約31、POT2約44、POT3約26、ENC4変化なし）を許容します。幅を超える変化が続く間は `c` を受け付けません。動作中の逆方向判定は、PWMが有効だった連続サンプル間だけで行います。目標許容差内でPWMが0になった後の受動的な戻りやADC揺れを、モーターの逆回転とは判定しません。駆動中に許容幅を超える逆行や進捗タイムアウトがあれば停止します。原点位置は操作者が目視で確認してください。

## 自動サイクル

1. EE初期化とENC4原点確認
2. EE準備完了通知後、アームが既存の初期化経路を実行
3. `/arm_xy/ready` と収穫状態が `APPROACH` になった後に視覚追従
4. `reason=approach_complete` かつ新しいsequenceと `hold_ready=true` の保持だけを収穫開始として受理
5. 収穫動作は1軸ずつ実行する。モータ2（POT2）→ モータ4（ENC4）→ モータ3（POT3）の順に、それぞれYAMLの目標値へ移動し、許容差内で安定確認して停止する。前の軸の到達確認前に次の軸は動かさない。収穫中、対象外軸が運転範囲外でも初期姿勢からの差が目標許容差内なら揺れとして受け入れ、軸を動かさない。許容差を超えて範囲外なら、順序を崩して別軸を動かさず停止してFAULTにする。
6. フック閉鎖後、既存pullサービスでアームを設定初期姿勢へ戻す
7. アーム復帰完了後、4軸を1軸ずつEE初期位置へ戻す
8. `WAIT_NEXT_CYCLE` で停止し、操作者が果実回収・フック状態を確認して `n` を押したときだけ追従再開

収穫工程では、POT2・ENC4・POT3をそれぞれの工程で目標許容差内に到達確認した後、後続工程やアーム復帰中に目標値からずれてもFAULTにしません。POT1のロールずれも同様に許容します。これらの軸を到達後に能動的に保持する機能はありません。センサー値の不正・通信断・動作タイムアウトは引き続き停止し、工程中の運転範囲外値は既存の範囲復帰処理で扱います。

2026-10-15 01:10の `arrival_check_20261015_011010` bagでは、POT2目標3150に対して閉鎖開始時は3101、閉鎖中は3101～3147でした。POT2が誤差36となり旧ドリフト判定でFAULTになった時点では、POT3=3300で目標3600まで300カウント残っていました。前段のピッチ目標到達・レール伸長後にPOT2が目標からずれていた状態を、閉鎖中に再度停止条件として扱っていたことが原因です。別の `arrival_check_20261015_005718` bagでもPOT2のずれで閉鎖が止まっていました。今回、到達後のずれによる停止判定を外します。設定範囲外の実値が機械的に安全であることを意味するものではないため、実機の姿勢・干渉・保持は別途確認してください。

注意点として、01:10のbagではPOT2がピッチ目標3150（センサー値3157）から、レール伸長後・フック閉鎖開始時に3101へ変わっています。実際のピッチ変位かセンサーの揺れかはbagだけでは区別できません。今回の変更は閉鎖の誤停止を避けるものですが、ピッチの保持精度を保証しません。実機ではレールを伸ばした状態のPOT2変化とフックの姿勢を確認してください。

起動時のEE初期化ではPOT1・POT2・POT3を同時に指令し、ENC4は手動登録した原点に保持します。各軸の目標許容差は、実測値が運転範囲の外にある場合にも適用します。たとえばPOT3の目標1500・許容差35なら、1465～1535は範囲外の値を含め到達扱いにします。目標許容差を超えて範囲外にある軸は、安全な内向きへ動かします。範囲外センサーの単独復帰と、アーム復帰後のEEリセットは1軸ずつ動かします。合計PWM制限にかかった場合も、最低PWMを保ったうえで余剰分を配分します。初期化3軸の最低値を保つには、`max_total_abs_pwm` をPOT1・POT2・POT3それぞれの最低値の合計以上に設定します（現在は540）。Pico側ファームウェアは `DRIVE` コマンドに対応している必要があります。

## キーと診断

- `c`: 収納端を目視確認した後、ENC4原点を登録
- `Space`: EEをSTOPし、自動サイクルを中断してアームへholdを要求
- `n`: EE初期化とアーム復帰の両方が済んだ待機状態から追従を再開
- 端末のない環境では `std_msgs/msg/String` の `/end_effector/auto/key` に `c`、`n`、`space` をpublishして同じ操作ができます。例: `ros2 topic pub --once /end_effector/auto/key std_msgs/msg/String "{data: n}"`

診断は `/end_effector/auto/state` のJSONに出ます。工程、センサー実測値、目標値、駆動PWM、センサー値の古さ、アーム状態、停止理由を含みます。`sensor_out_of_range` には各軸が設定範囲内か、下限外か、上限外かと、許可される復帰方向も出ます。アーム側は `/arm_xy/harvest/state`、カメラ側は `/vision/servo_diagnostics` をrosbagに記録できます。

POT/ENCの実測値が設定した運転範囲を外れていても、POTが12-bit ADC範囲（0～4095）、ENC4が符号付き32-bit範囲内なら、値の読み取り自体はFAULTにしません。実測値が現在工程の目標許容差内なら、範囲外でもその軸を停止し、範囲端まで余分に押し戻しません。通常の初期化・リセット工程では、許容差を超えて範囲外にある軸や現在工程の目標に含まれない範囲外軸を、工程指令の前に1軸ずつ範囲内へ戻します。収穫の1軸シーケンス中は別軸を動かしません。対象外軸が初期姿勢の許容差を超えて範囲外なら停止してFAULTにします。範囲外からさらに外へ進む指令はPWM=0にします。センサー生値そのものが不正、通信が古い、または復帰進捗に異常がある場合も停止してFAULTになります。

全設定は `src/end_effector_pkg/config/auto_harvest.yaml` にあります。PWMの`min`と`max`は`pot1`・`pot2`・`pot3`・`enc4`ごとに設定し、現設定は各軸140～220です（POT1=M1、POT2=M2、POT3=M3、ENC4=M4）。3軸同時初期化で各最低PWMを維持するため、`max_total_abs_pwm`はPOT1～POT3の最低値合計以上にしてください。2026-10-14の自動運転ログでは、M2へ正PWM=180を指令した後にPOT2が56カウント減少したため、設定上のM2方向を反転しました。過去の手動確認記録とは食い違うため、次の実機試行では低リスクな姿勢・短い時間でPOT2の増減方向を再確認してください。指定値はカウント値で、角度・cmへ換算しません。

## 検証範囲

2026-10-16の `arrival_check_20261016_140216` bagでは、到達条件のうち画素誤差は記録された接近中の全サンプルで許容内でした。一方、最新の目標位置と実測FKの差5mm以内というコード内の固定条件は約半分のサンプルしか満たさず、他の条件と同時に連続0.6秒満たせる時間が短くなっていました。このため到達時の関節速度上限を0.03から0.06rad/s、最新目標と実測XYの許容差を5mmから設定可能な15mmへ変更しました。横画素誤差50px、距離誤差6mm、yaw誤差0.03rad、安定時間0.6秒は維持します。保持後に実測停止を3周期確認してからEEへ許可します。bag記録値に対する事後評価では、到達候補を従来より早く連続して作れる見込みですが、実機で同じ時間短縮を保証するものではありません。

同bagでは、POT3は目標許容差70カウント内に入り、PWMが0になった後、センサー値が3451から3521、次に3465へ変動しました。PWM停止中に保存された3521を次の駆動サンプルと比較し、差分-56を「逆方向」としてFAULTにしていました。これは停止後のセンサー変動であり、bagから実モーターの逆回転とは判断できません。方向判定の基準値をPWM=0で破棄し、モーターを駆動していた連続サンプルだけを比較します。POT1～3にも同時の値変動が見られるため、ADC基準電圧・GND・電源ノイズ等は可能性として残り、実機で原因切り分けが必要です。運転範囲や逆方向許容値は緩めていません。

2026-10-14の模擬サイクル検証は、旧来のEE駆動順序とM2方向設定で実施しました。今回の起動時3軸同時初期化とM2方向反転は、その検証結果には含まれません。確認結果は `src/vision_pkg/validation/auto_harvest_sim_summary.json` とログに保存しています。

同日、PlatformIOでRP2350用UF2を完全ビルドし、Pico 2 W（シリアル番号 `A437E4B324D4447A`）へ書き込み、フラッシュ照合`OK`を確認しました。再接続後の読み取りではPWMは全軸0、ENC4=0、POT1≈1886、POT2≈2760、POT3≈1476でした。POT3は設定下限1500より24カウント低い一方、初期目標1500との差は許容差35カウント内です。この修正後の動作ではPOT3を範囲端まで押し戻さず停止扱いにします。この修正後に当該Picoへモーター指令は送っていません。実機で初期化を開始する前に、原点と目標値を確認してください。

模擬試験は、実機センサーの方向・範囲・PWM応答、Picoのwatchdogが実機で停止すること、フックが果梗に掛かること、果実を保持できること、もぎ取り力、電源・温度・機械干渉を保証しません。設定範囲外の値からの補正は生値の妥当性を確認した上で行い、実機起動前に復帰方向の機械的余裕、POT値・ENC4方向、原点、PWMとタイムアウトを確認してください。
